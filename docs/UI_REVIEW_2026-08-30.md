# KPI-карточки: переполнение и понятность

## Область

Исправлен блок «Куда ушли деньги» по пользовательскому скриншоту, включая соседнюю таблицу юнит-экономики. Это не полный аудит всех экранов и не изменение финансовых формул.
Изменения подготовлены локально; production не обновлён.

## Найдено и исправлено

- При viewport 1280 px исходная сетка давала карточкам 157 px. Русский статус рекламы занимал 289 px, статус расчётов — 231 px. Причина: шесть колонок и white-space:nowrap на статусах.
- Сетка теперь 3/2/1 колонки в зависимости от ширины; статусы и длинные значения переносятся без обрезания. Таблица юнит-экономики переносит длинные подписи. На телефоне шапка не перекрывает содержимое.
- Цвет стрелки больше не зависит от статуса текущего уровня. Снижение маржи красное даже при положительной марже; рост возвратов красный даже ниже порога предупреждения. Расходы на рекламу не получают автоматическую оценку «хорошо/плохо» по одному направлению изменения.
- Доли сравниваются в процентных пунктах по change_abs из API. Остальные показатели используют change_pct из API. Финансовые суммы не пересчитываются в интерфейсе.
- Показаны предыдущее значение и точные даты сравнения. Если в предыдущем периоде меньше пяти заказов, показано предупреждение о малой выборке.
- Удалено обещание несуществующего клика по карточке. Добавлены раскрываемые пояснения с формулами и ограничениями для всех 12 KPI, доступные с клавиатуры.
- «Покрытие расчётами» заменено на «Заказы с финальным расчётом». Пояснено, почему финальный расчёт TikTok не равен поступлению денег в банк.
- Разделены расходы магазина и оценочное распределение рекламы по заказам. Текст не заявляет точную атрибуцию кампаний.
- Устранён вывод технических note.* ключей в английских примечаниях.

## Проверка

- Browser: RU viewport 360, 768, 1024, 1280, 1920 px — все 12 карточек без горизонтального переполнения (scrollWidth <= clientWidth); проверено раскрытое пояснение на телефоне. EN — без переполнения и технических ключей в примечаниях.
- 6 frontend regression-тестов: падение маржи, возвраты с нулевой базы, улучшение возвратов, неизменность, нейтральные расходы, сокращение убытка, отсутствие данных.
- TypeScript, ESLint и production build прошли.
- Независимое и подтверждающее код-ревью: actionable findings отсутствуют.

Демо использует фиксированные fixtures, а не текущие данные магазина. Скриншоты демо подтверждают вёрстку и поведение, не финансовую сверку. Полная локализация динамических объяснений API в остальных разделах остаётся отдельной задачей.
