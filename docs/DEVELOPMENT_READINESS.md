## Что представляет собой проект

Lomira / TikTok Shop Profit Control: FastAPI + SQLAlchemy/PostgreSQL, детерминированная финансовая аналитика, Shop/Ads/Telegram адаптеры, ingestion и APScheduler worker, Next.js 15 / React 19 dashboard.
Данные проходят raw → normalized → analytics. Деньги считаются через Decimal; бизнес-день Asia/Jakarta. Ads-атрибуция BLENDED не является точной атрибуцией кампаний.

Входные документы: `CLAUDE.md`, `docs/SPEC.md`, `HANDOFF_2026-08-31.md`, `docs/dashboard-api.md`, `docs/reconciliation-2026-08.md`.
Handoff датирован следующим днём относительно локальной даты и отстаёт от HEAD: frontend уже закоммичен. Данные о VPS, подключении магазина, сверке финансов и Ads approval — исторические заявления handoff, не проверка текущего сервера.

## Подготовленная среда Windows

- Python 3.12.13: `.venv`, зависимости `.[dev]` установлены; снимок версий `.tools/python-environment.txt`.
- Node из комплектного runtime, локальный npm 10.9.3 в `.tools/package`; `npm ci` выполнен по исходному package-lock.json без его изменения.
- `.env` создан из примера с localhost для БД/Redis и пустыми секретами. БД/Redis локально не подняты.
- `.tools`, `.venv`, `.env` и генерируемые frontend-файлы игнорируются Git.
- `scripts/dev-shell.ps1` подключает инструменты к текущему PowerShell и исправляет путь HTTPS-helper комплектного Git, не меняя системные настройки.

```powershell
. .\scripts\dev-shell.ps1
npm --prefix apps/dashboard run typecheck
npm --prefix apps/dashboard run lint
npm --prefix apps/dashboard run build
.\scripts\dashboard-mock.ps1
```

Последняя команда запускает только фикстуры на `http://127.0.0.1:3400`; Ctrl+C останавливает сервер. Mock не обращается к TikTok, задачи живут в памяти. Старые разделы используют статические фикстуры; новый журнал заказов поддерживает фильтры, даты и пагинацию на демонстрационных данных. Не использовать его числа для бизнес-решений.
Скрипты рассчитаны на подготовленную среду; на другом компьютере нужны Node/npm и установка зависимостей.

## Проверки и ограничения

- Frontend: TypeScript, ESLint и production build прошли. Next.js требует разрешения среды на дочерние процессы; в песочнице получен spawn EPERM, вне неё сборка завершена успешно.
- Python: Ruff по src/apps/api/apps/worker/tests прошёл.
- Mock HTTP smoke: `/`, `/api/dashboard/overview`, `/api/analytics/video-products`, `/api/tasks` ответили 200. Визуальное browser QA не выполнялось.
- Pytest: **265 passed, 3 failed, 8 collection errors**, с `--continue-on-collection-errors`; это частичная проверка, не зелёный весь набор. Лог: `.tools/pytest-baseline.txt`.
- Причины: Linux-only `fcntl` в Shop client (в том числе транзитивные импорты API/worker) и Unix mode 0600 в тесте TokenStore. Блокировки не подменялись заглушками.
- Alembic source head: `a9c4e7f1b2d3`; миграции к БД не применялись.
- Docker не найден, WSL не установлен. Полный backend требует Linux/WSL или Docker. Установка системных компонентов и перезагрузка не выполнялись.
- Python зависимости имеют нижние границы без lockfile; локальные версии могут отличаться от VPS.

## Приоритеты следующей работы

1. Получить Linux-среду для backend: Docker Desktop/WSL либо изолированная Linux development-машина. Повторить весь pytest, поднять отдельные PostgreSQL/Redis, применить миграции к dev-БД. Не использовать production как тестовую среду.
2. Проверить доступ к дашборду/API: в приложении нет auth, Caddyfile не задаёт защиту, compose публикует API/dashboard порты. Наличие внешней защиты VPS не установлено. Не открывать финансовые данные без проверки и защиты доступа; проверить OAuth state.
3. Пройти интерфейс и API совместно на dev-данных: периоды/сравнение, null и ошибки, provisional/settled, создание и изменение задач. Прямой запрос браузера с :3400 на :8400 потребует CORS или same-origin proxy; текущий FastAPI CORS не настраивает.
4. Подтвердить timezone analytics и качество данных. Не снижать пороги достаточности выборки только ради появления рекомендаций.
5. Проверить текущий статус Ads approval и подключить read-only Ads после одобрения. Секреты вводятся в защищённой среде, не в чате или Git.
6. Только затем LLM-объяснения и новые рекомендации. Для функциональных изменений: план → минимальный diff → полный набор тестов → независимое ревью → исправления → подтверждающее ревью; деплой отдельно.

Никакие рекламные бюджеты, TikTok данные или production-конфигурация во время подготовки не менялись.
