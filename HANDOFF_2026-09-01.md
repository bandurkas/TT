## 2. ⚠️ Manual ad-Cost entry corrupted live data twice today

Ads Manager reports **the selected date range**. `POST /api/advertising/manual` takes **one day**, and a newer observation silently replaces the previous one. On 2026-09-01 that misfired twice within an hour:

| time | entered | dashboard then showed |
|---|---|---|
| 21:28 | `2000`, sku_orders 0, gross 0 | **+414,200 profit, +62% margin** |
| 22:08 | `5,062,670 / 87 orders / 8,636,752` | **−4,646,470, −697% margin** |

The second is plainly a month's figures — that day the shop did 8 orders, 10 units, 825,000 GMV. Both restored by re-posting the real day; superseded `SourceReport` rows stay in the audit trail, so nothing was lost.

**Current, correct state for 2026-09-01:** Cost `450,000`, sku_orders `10`, gross `810,904` → **net −33,800, margin −5.07%**, still `partial` (day open).

**Proposed guard** — two deterministic checks in `record_manual_ad_day()`, each returning 422 with a plain message unless an explicit `confirm` flag is set:
1. entered `sku_orders` or `gross_revenue` exceeds the day's own actual units / GMV by more than ~2× → "these look like period totals, not one day";
2. the new cost is a small fraction of the observation it would replace, or it zeroes fields that were non-zero → "this would overwrite a fuller record".

Plus make the single-date scope unmissable in the form itself.

Do **not** "solve" this by splitting a range across days. Allocating a period's Cost per day is an invented number, which SPEC §2 and `CLAUDE.md` forbid outright.

## 4. Infra: the repo moved off iCloud — `~/Desktop/TT` → `~/dev/TT`

`~/Desktop` is iCloud-synced, and it was actively syncing `apps/dashboard/node_modules` (~180 MB, tens of thousands of files). Symptoms it caused: `next dev` bound its port but never answered a request; `npm run build` failed with `ENOTEMPTY`/`ENOENT` and needed 2–3 attempts; copying `node_modules` off Desktop ran at ~100 KB / 20 s. Worst of all, **`.git/refs/heads/main` was missing**, left as an unrenamed `main.lock`, so every git command answered *"branch main does not have any commits yet"* — recovered by renaming the lock back to the ref (the sha inside was correct and the object intact).

After the move: `npm ci` 9 s, `next dev` ready in 2.3 s, `npm run build` green on the first attempt in 33 s.

**Other projects are still on `~/Desktop` (BUBU, Jony, PS_2026, Gefest…) and carry the same risk.** Before moving one: delete `node_modules` / `.venv` / `.next` first, or `mv` spends hours re-downloading cloud-evicted files.

## 9. Reference: API contracts for the two entry features

**`POST /api/advertising/manual`** `{date, cost: string, sku_orders, gross_revenue: string, final: bool, note}` → 201 `{report_id, partial, unchanged?, recomputed:{orders, inserted}, day:{...}}`; 422 with a `detail` string (newer entry exists / future date / final on an unfinished day). Only a *newer* observation may replace a day; `final=true` closes it. `shop_ad_days.manual` marks per-order snapshots `ad_source=manual_entry_cost` rather than `campaign_overview_cost`.

**`GET /api/advertising?from&to`** → `{cost, known_cost, gmv_pay, covered_days, expected_days, missing_days[], partial_days[], status, source, manual_days, entry_note, reports[], days[]}`; `days[].source` is `"shop_overview" | "manual_entry"`. Also embedded as `overview.advertising`.

**`GET /api/costs?from&to`** → `{default_cogs_per_unit, lots[], skus[], note}`.
`lots[]`: `{id, scope "all"|"product"|"sku", product_id, sku_id, received_on, unit_cost, quantity|null, currency, note, active, consumed?, remaining?, shared_skus?}`.
`skus[]`: `{sku_id, external_sku_id, product_id, product_title, sku_title, current_cost, source "lot"|"seed"|"default"|"none", lot_id, effective_from, history[]}`.
Writes: `POST /api/costs/default`, `POST /api/costs/lots` (201), `PATCH /api/costs/lots/{id}` (`quantity: 0` clears to "until next lot"). Every write rebuilds FIFO versions, recomputes profit and aggregates synchronously, and returns `recomputed:{orders, inserted}`.

**FIFO semantics** (`src/domain/costs.py`): a `scope=all`/`scope=product` lot's `quantity` is one shared purchase batch, consumed against the **combined** sales of every SKU it covers, not per SKU. A lot without a quantity applies until the next one. A SKU's seed/manual cost still covers the time genuinely before its first lot. The worker rebuilds versions at the top of every `_compute_profit()`, otherwise lots freeze once exhausted.
